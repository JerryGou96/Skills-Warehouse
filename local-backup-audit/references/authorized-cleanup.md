# Authorized backup cleanup

1. State the exact absolute target paths and protected live-data paths before acting, because backup removal and file-level deduplication have different recovery consequences. Treat a clear request to delete previously audited old backups as whole-backup removal; ask one scope question only if the intended targets or retention choice remain ambiguous.
2. Recheck each target with `Path.exists()`, `Path.is_symlink()`, and `Path.resolve()` and inspect LaunchAgent/LaunchDaemon plist references with `plistlib` plus `ps -axo pid,args`, because a former backup may now be active. Print only matching paths or process IDs, not credential-bearing configuration or command lines. Stop on active references or path uncertainty.
3. Capture `df -k /System/Volumes/Data` immediately before cleanup and keep the Available KiB value, because APFS shared extents make logical duplicate bytes a poor prediction of reclaimed space.
4. For whole-backup removal, use an explicit allowlist of validated targets and the approved deletion tool; a Python implementation uses `shutil.rmtree(path)` for directories and `Path.unlink()` for files after parent, symlink, and protected-path checks. Do not broaden the allowlist to internal application backups, update captures, independent knowledge stores, or live state. Honor tool approvals and the agreed recoverable-versus-permanent removal scope.
5. For explicitly selected file-level deduplication, compare regular files at matching relative paths against the retained backup using size and streaming SHA-256. Skip symlinks and symlinked ancestors; recheck device, inode, size, mtime_ns and ctime_ns after hashing and before unlinking, because files can change during comparison. Preserve missing-target, differing, changed-during-scan and unreadable files; count errors separately.
6. Label deduplicated roots as difference-only remnants, not complete backups, because matching files no longer exist there. Record each removed path and its retained counterpart in a compressed audit manifest; do not claim restoration was tested unless it was.
7. Collect the original operation’s terminal result and verify each whole-removal target is absent with `Path.exists()` while protected roots remain present. Do not relaunch a completed cleanup or describe completed output as still running.
8. Repeat `df -k /System/Volumes/Data` and report `(after_available_kib - before_available_kib) / 1048576` as the observed net GiB change, because concurrent system activity can affect the delta. Use `du -sk` only for remaining directory-accounted sizes, not proof of physical space recovery.
9. Supersede earlier recovery guidance when an authorized later deletion removes its retained backup, because an audit manifest is not a restore source. Report concise Chinese results: exact scope removed, failures or retained remnants, protected live data, net free-space change, and current available space.
