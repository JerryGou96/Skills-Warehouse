# Compare X collection interfaces

1. Fetch `https://docs.x.com/x-api/lists/list-tweets/introduction` and `https://docs.x.com/x-api/getting-started/pricing` with web_fetch; verify the current list endpoint and billing units rather than repeating historical subscription tiers. Describe developer credentials and user authorization separately from browser login.
2. Fetch `https://docs.twitterapi.io/api-reference/endpoint/list_timeline` and `https://twitterapi.io/pricing`; check list-specific charges separately from general per-tweet rates because the pricing page distinguishes them. Confirm the documented list ID, cursor, next-page fields, and authentication before claiming integration support.
3. Inspect `https://github.com/vladkens/twscrape` and, when considering Twikit, `https://github.com/unclecode/twikit`; separate documented capabilities and maintainer claims from tested operation. Explain that local authorized sessions avoid a data-provider fee but still require maintenance when internal interfaces change.
4. Present official API, hosted third-party API, and local open-source collection as distinct options; compare authorization, billing units, pagination, maintenance, and evidence of coverage rather than treating them as interchangeable. Link primary documentation and label untested private-list, subscriber-post, long-text, and historical access as unverified. Do not purchase access or transmit login cookies as part of an informational comparison.
5. Propose a same-list, same-window comparison before replacing a collector; compare unique status IDs, timestamps, full text, replies, and reposts against the authorized browser view. Treat this as a proposed test until run, because documented pagination does not establish complete retrieval.
6. Explain that scheduled incremental collection with deduplication and gap records improves retrospective coverage; do not promise exhaustive history merely because a provider exposes an API.
