# Local backup audit

1. Treat an audit request as read-only authorization: inspect backup data and configuration without deleting, moving, or rewriting them, because cleanup requires a separate decision. State this boundary briefly in the user’s language.
2. Establish storage pressure on macOS with `df -h /System/Volumes/Data` and check snapshots with `tmutil listlocalsnapshots /`. Report an empty snapshot listing only as no listed local Time Machine snapshots, not as absence of all backups.
3. List home-directory entries first with Python `Path.home().iterdir()`, then inspect likely backup, recovery, migration, archive, and update-capture paths. Bound recursive discovery by depth and prune Library, .git, node_modules, virtual environments, and caches; record exclusions so a targeted scan is not described as a whole-disk audit. Do not follow symlinks.
4. Size each candidate once with `du -sk <candidate-paths>` and drill into large copies with `du -k -d 1 <candidate>`. Convert KiB to GiB by dividing by 1048576. Label these as directory-accounted sizes rather than guaranteed reclaimable bytes, because APFS clones can share extents. Keep active state directories separate from cleanup candidates.
5. Inspect backup scheduling with `crontab -l` and Python `plistlib` over `~/Library/LaunchAgents/*.plist`. Extract labels, script paths, and schedules instead of printing entire configurations or environment values, because these may contain credentials. Distinguish no user crontab from permission or command failures; qualify conclusions by the scheduler surfaces inspected.
6. Compare likely sibling copies by relative path using `os.walk`, `Path.stat().st_size`, and streaming `hashlib.sha256()` with 1 MiB reads. Build one index per root and reuse computed digests across pairwise comparisons to avoid rescanning. Skip symlinks and count read errors separately. For an initial payload comparison, explicitly exclude directories named .git, .venv, venv, browser, codex-home, extensions, node_modules, plugins, sandbox, and sandboxes; do not infer identity of excluded trees.
7. Report each pair’s identical-file count, identical bytes, changed common paths, and paths unique to each side. List differing and unique paths without exposing their contents. Do not sum pairwise duplicate byte totals across three or more copies, because the same payload can occur in several comparisons. Treat exact file hashes as evidence of file identity, not proof that whole backups are interchangeable.
8. Track each long-running command using its returned process handle and collect its terminal result before concluding. Reuse completed results rather than launching the same scan again. Stop only an identified audit-owned scan when abandoning an overly broad traversal, then disclose the resulting coverage limit.
9. Present a short Chinese summary unless the user requests another language: confirmed overlap, candidate paths and sizes, preservation recommendation, and remaining verification. Preserve the live directory and at least one recovery point while unique-content and restore checks remain outstanding. State whether compressed archives were only sized or actually verified; a filename and size do not prove archive integrity.
10. When a report artifact is appropriate, save only paths, counts, sizes, exclusions, and recommendations, then read it back to check the claims. Ask for separate cleanup authorization rather than treating highly overlapping copies as safe to delete. Once authorized, distinguish deletion of whole old backups from deduplication within backups; follow `references/authorized-cleanup.md` for the selected scope and actual space verification. Apply a clarification to the existing task rather than silently substituting file-level deduplication for requested backup removal.
