# Discord portal and channel setup

1. Use browser profiles, tabs and a labeled Developer Portal tab to find the existing application; read its application ID from the visible URL before proceeding so retries do not create duplicate bots.
2. Open Bot, enable Message Content Intent, save, and re-read its checked state. Leave unrelated privileged intents unchanged. For a covered switch, inspect its visible label and associated input; use the label or normal keyboard navigation, then verify state before saving.
3. Invite the confirmed application using `https://discord.com/oauth2/authorize?client_id=<applicationId>&scope=bot%20applications.commands&permissions=117760&guild_id=<guildId>&disable_guild_select=true` for View Channels, Send Messages, Embed Links, Attach Files and Read Message History. Verify those five permissions on the authorization page instead of requesting Administrator. If Discord hands the flow to its desktop app, use Continue using Discord to return to the web authorization UI. Stop for human CAPTCHA or authentication. Require the visible success page naming the intended server before claiming the bot joined.
4. Launch bare `openclaw channels add` in an interactive operator terminal for masked credential entry. Follow Discord → Modify settings → Add a new account → account ID → token entry, then choose Finished at the bottom of the platform menu, route the account to the intended agent, and wait for Channels updated. Do not reopen Discord from the platform menu merely because the new account is not yet persisted. Inspect only redacted progress and account metadata; never expose token-bearing terminal lines or full account configuration.
5. If a dedicated private channel is authorized, create it under the intended category, enable Private Channel, select the new bot role, and submit once. Read the resulting channel link to obtain its ID; verify the private-channel indicator and do not add unrelated roles.
6. Inspect existing account guild configuration before setting a narrow allowlist. For a new empty account, set `channels.discord.accounts.<accountId>.guilds` with `openclaw config set <path> <json> --strict-json`, where JSON is `{ "<guildId>": { "channels": { "<channelId>": { "enabled": true, "requireMention": false } } } }` when the user wants direct conversation without mentions. Merge existing approved entries for an established account rather than replacing them.
7. Verify `openclaw agents bindings --json` routes the actual saved account ID to the intended agent, then run `openclaw channels status --probe`. Require configured, running, connected and the intended channel permission audit; an empty guild allowlist can block inbound messages even when the token works.
8. Send one labeled test through the available message tool using the exact account and destination, and require its platform receipt. Ask the user to send a greeting in the channel and verify the agent reply separately; outbound delivery alone does not prove inbound routing. Report whether credentials were saved and used without repeating them.
