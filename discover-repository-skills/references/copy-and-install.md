# Copy and install discovered skills

## Repository copy

1. Confirm the target owner, repository name and visibility before creating a repository; explain that a slash separates owner/repository rather than belonging inside a repository name. Check for an existing target with `gh repo view OWNER/REPO --json nameWithOwner,url,isPrivate` to avoid duplicates.
2. Read the upstream license with `gh api repos/OWNER/SOURCE --jq '{default_branch,license:.license.spdx_id}'`; preserve the license text and required attribution with the copied files.
3. Clone upstream into a temporary directory using `gh repo clone OWNER/SOURCE TEMP/upstream -- --depth 1`, and record `git -C TEMP/upstream rev-parse HEAD` in ORIGIN.md. Copy each entire skill directory, including README and references, into `skills/NAME/`; copying only SKILL.md can break relative links.
4. Add a repository README distinguishing skill instructions from runtime dependencies; document external plugins as dependencies rather than implying their implementation was copied. Compare imported files byte-for-byte with upstream before committing.
5. Initialize and commit the selected files, then use `gh repo create OWNER/REPO --private --description DESCRIPTION --source . --remote origin --push` only for an authorized private repository creation. Substitute the agreed visibility when different. Verify the remote tree with `gh api "repos/OWNER/REPO/git/trees/main?recursive=1" --jq '{sha,files:[.tree[] | select(.type=="blob") | .path]}'`; a local commit alone does not prove upload.

## Publish a local skill into an existing repository

1. Resolve shorthand repository names with `gh repo list --limit 100 --json nameWithOwner,description`, then run `gh repo view OWNER/REPO --json nameWithOwner,url,isPrivate,defaultBranchRef`; use the existing repository and preserve its visibility rather than creating a duplicate.
2. Clone the target with `gh repo clone OWNER/REPO TEMP/target -- --depth 1` and inspect its AGENTS.md, README.md, ORIGIN.md, license and skill layout; merge the new entry without replacing existing readers or documentation.
3. Copy only `WORKSPACE/skills/NAME/` into `TEMP/target/skills/NAME/`, including scripts and references; exclude captured messages, reports, credentials, node_modules, delivery state, locks and caches because publishing a procedure does not authorize publishing its private inputs.
4. Add the README entry and distinguish locally authored workflow provenance from third-party imports in ORIGIN.md; preserve existing license attribution instead of attributing new code to the imported upstream project.
5. Inspect script-relative workspace resolution, absolute paths and external imports, then document the required installation layout, runtime version and dependency installation command; state that cloning a skill neither installs dependencies nor enables its scheduled jobs.
6. Run the installed skill-creator validator against the copied directory, `node --check PATH/script.mjs` for JavaScript helpers, and Python `compile(source, filename, 'exec')` for Python helpers; compare source and destination with `diff -r WORKSPACE/skills/NAME TEMP/target/skills/NAME` before staging, without executing private-data capture merely to validate publication.
7. Stage only the selected paths with `git -C TEMP/target add README.md ORIGIN.md skills/NAME` and inspect `git -C TEMP/target diff --cached --stat`; commit and push to the verified branch using the repository's protection rules, without force-pushing.
8. Verify the pushed SHA and complete skill file tree with `gh api "repos/OWNER/REPO/git/trees/BRANCH?recursive=1" --jq '{sha,truncated,files:[.tree[]|select(.path|startswith("skills/NAME"))|.path]}'`; return a concise Chinese confirmation with the direct skill-directory link, commit, included resources and excluded private data.

## Local installation

1. Read the available installer skill and select the actual agent skill directory; do not assume a Codex installer default also registers skills with OpenClaw. For a shared OpenClaw installation, use the verified `${OPENCLAW_SKILLS_DIR}` destination explicitly.
2. When the installer is available, use its discovered script path with `--repo OWNER/REPO --path skills/NAME_A skills/NAME_B --dest DEST --method git`; Git mode supports private repositories through existing credentials. Preserve existing skill directories instead of overwriting them blindly.
3. Inspect dependencies using `command -v opencli`, `node --version`, and `npm --version`; read the copied SKILL.md and plugin README before installing dependencies. Follow current tool permissions and plugin-installation policy even when upstream instructions recommend installation.
4. When authorized and permitted, install opencli with `npm install -g @jackwener/opencli`. For the documented TradingView adapter, use `opencli plugin install github:himself65/finance-skills/tradingview`. Inspect installation warnings, then run `opencli plugin list` to verify actual loaded commands rather than treating a package-manager success message as readiness.
5. Probe `opencli tradingview status` and inspect the returned `connected` field; a successful process or `ok:true` response can still report no desktop connection. Do not use a status pipeline ending in `head` plus an unconditional READY echo, because it can mask failures.
6. Preserve the requested access route: when the user requests `discord-reader` through Discord Desktop, read that skill and inspect its desktop adapter instead of substituting bot message tools or requiring a bot invitation. Treat any actual access denial separately; establish its scope before proceeding and never use another client to bypass a restriction.
7. Check adapter command availability with `opencli --help` and `opencli discord-app --help`. If the documented command is absent, inspect adapter history with `gh api "repos/jackwener/opencli/commits?path=clis/discord-app&per_page=3" --jq '.[] | {sha,message:.commit.message}'`, then inspect the relevant parent revision and package version. For an authorized compatibility installation, preserve the global runtime and install a pinned release in an isolated directory: `npm install --prefix RUNTIME --ignore-scripts --save-exact @jackwener/opencli@1.8.7`. Replace RUNTIME with the task workspace runtime directory. Run `RUNTIME/node_modules/.bin/opencli discord-app --help` and confirm `status`, `goto`, `read`, and `search` are listed. This verifies command availability only, not desktop connectivity or successful message capture; use only the read-only commands and follow applicable installation policy.
8. Separate installation from application launch. Check installed desktop applications before connection testing, and obtain approval before a relaunch that quits an existing application; TradingView launch can discard unsaved layouts. Do not read account-bound watchlists or private messages merely to prove installation.
9. Report skill files installed, dependencies verified, connection state, and any precise remaining blocker separately; do not label the whole integration ready when only instructions have been installed.
