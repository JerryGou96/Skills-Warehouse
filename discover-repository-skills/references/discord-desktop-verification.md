# Verify Discord Desktop reading

1. Read the installed discord-reader SKILL.md and use the user-requested desktop route; do not substitute bot membership or bot allowlist configuration for desktop setup. Honor actual tool denials within their scope and resolve ambiguous restrictions before accessing data.
2. Set CLI to the verified compatible executable; for the isolated runtime used here, use `${DISCORD_READER_RUNTIME}/node_modules/.bin/opencli`. Run `OPENCLI_CDP_ENDPOINT=http://127.0.0.1:9232 "$CLI" discord-app status -f json`; inspect the returned page URL and title as well as connection state, because a connected Discord Updater splash is not a ready channel.
3. When desktop launch is authorized and the endpoint is unreachable, run `open -a Discord --args --remote-debugging-port=9232`, then recheck status. Do not quit an already-running application without approval; if it ignores new launch arguments, report that a relaunch is needed. Keep endpoint settings per invocation instead of modifying shell configuration unnecessarily.
4. Run `OPENCLI_CDP_ENDPOINT=http://127.0.0.1:9232 "$CLI" discord-app servers -f json` and match the requested guild ID, because visible names can be ambiguous. Keep unrelated server names out of the reply.
5. Open the user-supplied target using `open "discord://discord.com/channels/GUILD_ID/CHANNEL_ID"`, then run `OPENCLI_CDP_ENDPOINT=http://127.0.0.1:9232 "$CLI" discord-app channels -f json`. Match the exact IDs rather than treating generic channel labels as proof of permission denial.
6. Run `"$CLI" discord-app read --help` before applying examples from the skill, because the tested adapter uses `--count` rather than a positional message count. Read a bounded sample with `OPENCLI_CDP_ENDPOINT=http://127.0.0.1:9232 "$CLI" discord-app read --count 20 --guild GUILD_ID --channel CHANNEL_ID -f json`. Use only read-only commands.
7. Verify returned channel_id, Author, Time, Message and message_id. Convert UTC timestamps to the requested local timezone and build source links as `https://discord.com/channels/GUILD_ID/CHANNEL_ID/MESSAGE_ID`; an actual message with matching IDs proves reading, while a status or channel listing alone does not.
8. Inspect long messages for abrupt endings and compare requested count with returned rows before claiming full capture. For complete commentary extraction or daily comparison, follow `discord-full-reports.md` to remove presentation clipping, load older rendered messages, verify continuation authors and assemble complete sections. Treat a bounded sample as partial evidence until those checks pass; an em dash alone does not verify author identity.
9. Reply in concise Chinese with whether messages were actually read, a relevant timestamp and source link, and any completeness limitation. Distinguish desktop connectivity, successful sample reading, complete report extraction, and scheduled delivery readiness.
