# Supply-chain matrix ingestion

1. Read the active vault protocol and search existing company and industry entries before archival, so the new image becomes a dated source rather than a replacement for prior research.
2. Locate the actual inbound attachment through available file or attachment tools and inspect it with view_image when necessary; preserve the original under the configured assets directory, because text alone loses visual evidence. Record the message source and receipt date; mark unknown author and publication date explicitly rather than treating receipt date as publication date.
3. Transcribe every row across every company into a rectangular matrix, because a thematic summary does not satisfy a request to remember who supplies each stage. Retain versions, percentages, server types, manufacturing levels, and parenthetical qualifications. Mark illegible text as unreadable and keep blanks distinct from N/A; neither establishes that no supplier exists.
4. Check dimensions with rows.every(row => row.length === companies.length + 1) and compute rows.length * companies.length before writing; compare every cell against the image, because rectangular shape alone does not establish transcription accuracy.
5. Separate source spellings from normalized aliases, because abbreviations can refer to different entities. Add Chinese/English aliases only when identity is established; leave unresolved abbreviations unchanged and record the identity question. Preserve source typos and place any normalization in a separate field.
6. Label the matrix as an unverified third-party source unless relationships have been independently checked, because archival is not verification. Record unknown date, chip generation, percentage denominator, and exclusivity scope. Keep GPU-server qualifications attached to HBM figures rather than assigning them to the customer's ASIC program.
7. Generate the master matrix and per-company lists from the same row data, so the views cannot drift through separate manual transcription. Embed the original image and source locator in the master note and link company entries to it. Distinguish platform suppliers from cloud buyers, because their columns may describe overlapping rather than additive demand.
8. Use vault-relative links and preserve prior dated entries when merging company and industry pages, because retrieval must retain historical context. Follow the current record and closeout procedure and inspect its schema first; use vault-relative source-note paths where required.
9. Await archival and indexing in dependency order, because searching during an unfinished refresh can produce misleading readiness state. Verify the note, image, accepted closeout where required, and current completed index; then search by company plus component and supplier name and confirm the new note appears.
10. Report the note title, companies, row/cell count, preserved original, and verification boundary concisely in the user's language. Provide future query examples without presenting local filesystem paths as remote downloads.
