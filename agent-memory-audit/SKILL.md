# Agent memory audit

1. Read installed OpenClaw memory documentation under `${OPENCLAW_INSTALL_DIR}/docs` before explaining product behavior. Use workspace instructions as evidence of local conventions, not proof of platform defaults. Keep this audit read-only unless repair is explicitly requested.
2. Run `openclaw agents list --json` to enumerate actual agent IDs and workspace paths. Read only memory-related configuration fields and each workspace AGENTS.md; avoid printing credentials or loading private MEMORY.md contents into a group discussion. Verify the inventory covers every configured agent rather than assuming the main agent represents all agents.
3. Run `openclaw memory status --json` and inspect each agent separately: backend, provider, sources, extraPaths, files/chunks, eligible file counts, dirty flag, full-text/vector availability, indexIdentity, and dreaming/audit fields. Distinguish configured retrieval from proven readiness; a configured embedding provider alone is not a successful live embedding test. Treat dirty or mismatched indexes as freshness warnings, not proof that source notes are lost. Do not equate indexed file counts with memories or facts.
4. Search memory for prior architecture decisions and label stale or partial retrieval. For an AgentBrain installation, read `${AGENTBRAIN_ROOT}/_meta/AGENTBRAIN_PROTOCOL.md` and `MEMORY_RULES.md`, then run `qmd query "agent memory shared isolation" -c agentbrain`. Inspect its freshness and embedding warnings before relying on results. Enumerate actual `agents/` and `shared/` directories and compare them with configured agent IDs; do not infer a specialist brain exists merely because an agent exists.
5. Inspect specialist retrieval instructions in each AGENTS.md, including dedicated corpus scripts and report folders. Distinguish conversational recall, durable research notes, and primary datasets: a newsletter archive, trading report directory, or market feed is not automatically part of memory_search. Confirm whether AgentBrain is included through sources/extraPaths or requires its separate QMD lookup.
6. Explain four layers: current session context and compaction; durable workspace notes such as `memory/YYYY-MM-DD.md` and `MEMORY.md`; derived retrieval indexes; specialist/shared knowledge stores. Describe chat-history retrieval separately and do not infer complete transcript indexing from the presence of saved sessions. Explain that reliable durable recall requires persistence and later retrieval, not merely having discussed something once.
7. Compare agents by their observed stores and retrieval mechanisms, then explain sharing boundaries. Label folder ownership and prompt rules as conventions unless actual permission enforcement was verified; shared filesystem access is not evidence of automatic cross-agent synchronization. State which newer agents lack matching vault directories without assuming that absence disables their ordinary memory.
8. Finish in concise Chinese when requested in Chinese: architecture, agent-specific differences, concrete freshness gaps, and verification limits. State whether anything was changed. Offer index refresh or configuration alignment as separate work; do not perform it while answering an explanation-only request.
